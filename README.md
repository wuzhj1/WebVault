# WebVault

[![CI](https://github.com/wuzhj1/WebVault/actions/workflows/ci.yml/badge.svg)](https://github.com/wuzhj1/WebVault/actions/workflows/ci.yml)
[![Deploy GitHub Pages](https://github.com/wuzhj1/WebVault/actions/workflows/pages.yml/badge.svg)](https://github.com/wuzhj1/WebVault/actions/workflows/pages.yml)

本地优先的 Markdown 双链笔记。纯静态单页应用，没有账号、没有后端：正文以明文 `.md` 存在浏览器里，通过**你自己的 Gitee 仓库**在设备之间同步。

**在线使用：<https://wuzhj1.github.io/WebVault/>**

> 站点只是个静态壳，不接收、也不存储任何数据——笔记始终只存在你自己的设备和 Gitee 仓库里。推到 `main` 由 [`pages.yml`](.github/workflows/pages.yml) 自动构建部署。

- 双链 `[[笔记]]`、别名 `[[路径|显示名]]`；`[[笔记#小节]]`、`[[笔记#^block]]`、`![[笔记]]` 会被解析并索引，在反链面板上标注出来，重命名时原样保留
- 编辑器里的双链**直接渲染成可点击的链接**：方括号和别名前的路径隐藏，只显示你要读的那段文字；已存在的笔记是实色胶囊，还没创建的目标是虚线灰字（点一下就建），附件用点线区分。光标进入某一行时该行自动展开成原始 markdown，方便改写链接本身
- 反向链接 / 出链 / 待创建目标面板，点击不存在的链接直接建笔记
- 右栏第三个页签是**大纲**：跟着打字实时列出本文标题（级数用缩进与 `#` 的个数表示），点一条就把编辑器滚到那一节并落光标。大纲从**编辑器的 IR DOM** 读而不是解析 markdown 源码——源码那套 ATX 正则抓不到引用块里的 `> # 标题` 和 setext 的 `标题` + `===`，而它们在编辑器里都是真标题，按源码顺序给 DOM 下标必然跳错位；反过来代码围栏里的 `# 代码` 渲染在 `<pre>` 里不是 heading，天然不进大纲
- 重命名或移动笔记时，全库指向它的 `[[双链]]` 自动改写
- 旧笔记里遗留的卡片盒元数据块（frontmatter 的 `id` / `type` / `tags` 等）**原样保留、永不改写**，`[[202609151423]]` 这样的永久 ID 链接依旧能解析、改名不断链
- **属性**（对标 Obsidian Properties）：编辑器上方一条可折叠的属性条，创建日期、标签、分类**以及任意自定义字段**都能就地增删改。字段类型可声明为 文本 / 列表 / 数字 / 勾选 / 日期（存 `.webvault/app.json` 的类型注册表），没声明的按值推断——所以桌面 Obsidian 或 VS Code 里写的属性，回来一样渲染得对。元数据**依然不进编辑器正文**：属性条只发一次改写请求，落盘顺序、缓存同步、并发串行与同步推送全由编辑器收口；分居两处迟早出现两份状态，而过期那份会在下一次自动保存里赢——表现就是「改了属性，打两个字就没了」。`id` 与 `date` 只读（换一天请走「移动笔记」，`date:` 的写入点仍是回填与搬进日期名文件那两处）；`created:` 只在新建时写入，存量笔记用设置 → 数据页的「补齐创建日期」一次性补（取文件最后修改时间，按钮上写明了这个口径）
- 侧栏是 44px **活动栏**：笔记 / 待建 / 标签 / 日历 / AI 五个图标切换右侧内容面板，图标上挂计数徽标；笔记 / 待建 / 标签 / AI 产出区能过滤，笔记区内**目录 / 置顶 / 最近**三个标签页切换视图（书签不再和目录树混排），点标签行直接全库搜索 `#标签`
- **日记日历**：归日看 frontmatter 的 `date:`（`date: 2026-10-10`），**搬动、整理、改名都不丢日期**；新建平铺落到 `日记/晨间.md`（同名自动退让成 `日记/晨间 2.md`），存量的一天一目录启动时一次性拍平。侧栏第五个分区**上半是周一开头的月历、下半是那一天的日记列表**，`‹ 年月 ›` 翻页 +「今天」归位；点月历格子选中那天（列表随之切换），点列表里的标题打开那一篇，列表头部「新建」就地输标题建文件，方向键在日期间漫游、跨月自动翻页且**顺带选中**，`Ctrl/⌘+Alt+D` 切到日历分区
- 中文全文搜索（自研 CJK 单字/双字分词 + MiniSearch），带命中摘要
- 力导向关系图谱，日记默认不进图（工具条可开「包含日记」）
- Vditor 即时渲染编辑器，`[[` 触发链接补全，资源全部自托管、离线可用
- 5 套主题（3 深 2 浅）× 8 种强调色，在设置的「外观」里点一下就换，编辑器、代码高亮、关系图谱一起跟着走
- PWA：可安装、可离线，Safari 清空缓存后能自动从 Gitee 恢复
- Gitee 单仓库同步：索引优先拉取、正文按需下载、批量提交、三方合并、冲突副本
- 浏览器直连的 AI 助手（自填 OpenAI 兼容接口，零后端）：侧栏对话、选区一键处理、整篇总结/标签/双链建议；AI 内容与自己的思考**分隔开**——对话历史不进笔记库，进笔记的 AI 内容必带标记，详见「AI 助手」一节

## 本地跑起来

```bash
pnpm install
pnpm dev           # http://localhost:5173
```

> 包管理器以 `pnpm-lock.yaml` 为准（`package-lock.json` 已入库移除并在 .gitignore 中，npm 误装不会污染仓库）。

不配置同步也能当纯本地笔记用，所有功能（双链、搜索、图谱）都在本机完成。

自检命令：

```bash
pnpm verify        # 18 个验证套件,1335 条断言(配置 / 解析 / frontmatter 与 ID 兼容 / 自定义属性 / 链接改写 / 三方合并 / 远端删除判定 / 搜索 / 主题 / 路径与标题 / 内容指纹 / 链接解析 / 落盘簿记 / ZIP 打包 / 凭据抹除 / 配置目录形状 / AI 标记与提示词 / 日历日期 / 大纲文本)
pnpm typecheck     # vue-tsc --noEmit
pnpm build         # 类型检查 → 生成 PWA 图标与 vditor 静态资源 → 产出 dist/
```

浏览器要求：Chrome / Edge 86+、Firefox 111+、Safari 15.2+，且必须是 **HTTPS 或 localhost**（OPFS 与 Service Worker 只在安全上下文可用，用 `http://` 打开会直接提示不支持）。

## 部署

`pnpm build` 产出 `dist/`，丢到任意静态托管即可：Nginx、Vercel、Netlify、Cloudflare Pages、GitHub Pages、Gitee Pages。

Service Worker 已配置 `navigateFallback`，深链接刷新能回到应用；托管侧最好也把未知路径重写到 `index.html`。`gitee.com` 的请求被强制设为 `NetworkOnly`，同步的正确性依赖每次拿到最新的 sha，绝不能吃缓存。

### GitHub Pages（当前线上）

线上地址：<https://wuzhj1.github.io/WebVault/>

推到 `main` 后由 [`pages.yml`](.github/workflows/pages.yml) 自动构建部署：产物经 `upload-pages-artifact` + `deploy-pages` 走 Actions 制品，**不往版本库提交 `dist`**。两个环境变量钉在 workflow 的 `env` 里：

| 变量 | 值 | 作用 |
| --- | --- | --- |
| `VAULT_BASE` | `/WebVault/` | Vite 的 `base`；静态资源路径、PWA 的 `scope` / `start_url` 跟着带前缀 |
| `VAULT_ORIGIN` | `https://wuzhj1.github.io` | canonical、`og:url`、`robots.txt`、`sitemap.xml` 的域名部分 |

几点前提：仓库 Settings → Pages 的 Source 要选 **GitHub Actions**（`deploy-pages` 只认这个来源）；`concurrency` 用的是 `cancel-in-progress: false`，后一次部署不会打断进行中的那次；`workflow_dispatch` 可以手动触发。下面两节讲的是这两个变量背后的通用做法——换到别的托管商时照那两节配。

### 子路径部署（Gitee Pages / GitHub Pages 项目页）

站点不在域名根目录时（例如 `https://user.gitee.io/my-vault/`），构建前要告诉 Vite 基础路径。在项目根目录新建 `.env.local`：

```
VAULT_BASE=/my-vault/
```

然后正常 `pnpm build`。`start_url`、`scope`、静态资源、Service Worker 回退路径、Vditor 的资源目录都会跟着加上这个前缀；`index.html` 的图标链接用 `%BASE_URL%` 同样带前缀。

> **Windows / Git Bash 注意**：不要用 `VAULT_BASE=/my-vault/ pnpm build` 这种命令行写法。MSYS 会把以 `/` 开头的参数改写成 Windows 路径（`/my-vault/` 变成 `D:/soft/Git/my-vault/`），构建结果全错。写进 `.env.local` 最稳妥；确实要用命令行就加 `MSYS_NO_PATHCONV=1`。`.env.local` 已被 `.gitignore` 的 `*.local` 规则忽略。

### SEO 与分享卡片

`index.html` 里的 canonical / `og:url` / `og:image`，以及构建时生成的 `robots.txt` / `sitemap.xml`，都需要**绝对地址**，由 `vite.config.ts` 的 `webvault:seo` 插件在构建期拼成 `<部署域名><base>`：

```
VAULT_ORIGIN=https://wuzhj1.github.io   # 部署域名，不含路径；默认值即当前线上站点
```

和 `VAULT_BASE` 一样写进 `.env.local` 即可；CI 里对应 `pages.yml` 的 `env`。`base` 那一半由插件现取，所以换到 Gitee Pages 子路径时地址会自动跟着对，这也是为什么这些文件不放在 `public/` —— 静态文件拿不到 `base`。

三处文案是各自独立的副本，改一处记得同步：`index.html` 的 `<title>`/`meta description`、`index.html` 首屏那段静态文案（`<div class="boot">`）、以及 JSON-LD 里的 `description`。

`public/og-cover.png`（链接分享图，1200×630）由 `scripts/og-cover.html` 经本机浏览器截图生成，**不挂在 `pnpm build` 上**（CI 的字体和本地不同，跑出来的图会漂）。改了源文件后在本机重新生成一次：

```bash
pnpm og     # 需要本机有 Chrome 或 Edge，可用 CHROME_PATH 指定
```

> 注意：爬虫只从**域名根**读 `robots.txt`。托管在 GitHub Pages 项目页这类子路径时，`dist/robots.txt` 落在 `https://<用户名>.github.io/<仓库名>/robots.txt`，爬虫不会去读它；要让它生效得去 `<用户名>.github.io` 用户站点仓库放一份。仓库里这份是为了换到自定义域名或根路径部署时开箱即用。

### Gitee Pages 流程

1. 把 `dist/` 的内容提交到一个仓库（这个仓库可以和存笔记的仓库分开，也可以就是同一个仓库的 `gh-pages` 之类分支）。
2. 在仓库的「服务 → Gitee Pages」里开启，拿到 `https://<用户名>.gitee.io/<仓库名>/`。
3. 按上面写 `.env.local` 再构建一次，重新部署。

## 第一次配置 Gitee 同步

1. 在 Gitee 新建一个**私有**仓库（例如 `my-vault`），**里面至少提交一个文件**——空仓库没有分支，推不上去。建议专门用一个仓库放笔记，不要和代码混在一起。
2. 打开 `gitee.com/profile/personal_access_tokens`，生成新令牌，**只勾选 `projects`**。
3. 在应用里按 `Ctrl/⌘ + ,` 打开设置 →「Gitee 同步」，填：
   - **私人令牌** access token
   - **空间地址** owner（用户名或组织名；直接把 `gitee.com/<owner>/<repo>` 的仓库地址整串粘进来也行，保存时会自动拆成 owner / repo / branch 三段）
   - **仓库名** repo
   - **分支** branch（默认 `master`）
4. 点「测试连接」，成功会显示分支、HEAD 短 sha 和文件数。
5. 点「立即同步」把远端笔记拉到本机。

首次同步只用一次 `trees?recursive=1` 请求建立整个文件索引，没下载正文的笔记是「仅索引」状态（设置 →「数据与日志」里能看到数量）；打开某篇时才按需下载正文，后台每轮预取 25 篇慢慢补齐。这样即使仓库里有几千篇笔记，第一次同步也不会打爆 Gitee 的接口配额。

「编辑后自动同步」默认开启，推送延迟默认 15 秒（停止输入 15 秒后尝试上传）。把延迟调长能减少提交次数，避免仓库塞满碎片提交。

## 装成应用（PWA / 添加到主屏幕）

- **桌面 Chrome / Edge**：地址栏右侧的安装图标，点一下就以独立窗口运行。
- **Android Chrome**：菜单 →「安装应用」或「添加到主屏幕」。
- **iOS Safari**：分享按钮 →「添加到主屏幕」。**必须这样做**，见下。

### iOS 上为什么要装到主屏幕

Safari 的防跟踪策略（ITP）会在大约 7 天不使用后清空该站点的全部本地数据，包括 OPFS 里的笔记正文。装到主屏幕能显著降低被清的概率，但并不能完全避免。

因此应用启动时会自检：如果 IndexedDB 的索引还在、OPFS 正文却空了，就判定为「浏览器清空了缓存」，自动从 Gitee 重新拉取全部正文并显示进度，完成后提示恢复了多少篇。也可以在「数据与日志」里手动点「清空并重新下载」触发同一条恢复路径（该按钮在还有待上传文件时是禁用的，防止覆盖掉未同步的修改）。

**前提是配了同步**。没配 Gitee 就只有一份本机数据，被浏览器清掉就是真丢了。

离线方面：应用外壳、样式、编辑器内核（Vditor 的 lute、图标、katex 等资源全部放在 `public/vditor`，不依赖任何外部 CDN）都在 Service Worker 的预缓存里，断网也能正常读写笔记，联网或切回前台时自动同步。

重新部署后不需要用户手动清缓存：Service Worker 是 `autoUpdate` 模式，新版本会在后台自动安装并接管，下一次刷新（或下一次打开已安装的应用）就是新版本。实测是「部署 → 打开一次触发更新 → 再刷新一次拿到新界面」。

## 侧栏与分区

**侧栏 = 活动栏 + 面板**：最左 44px 图标竖条（Obsidian / VS Code 式）切换右侧内容面板，选中图标带 accent 淡底与左缘指示条，笔记 / 待建 / 标签 / 日历 / AI 图标挂计数徽标（99 以上显示 `99+`，活儿多的用暖色底），竖条底部的 ＋ 在任何分区下都能一键新建笔记。日历的徽标是「有日记的天数」，与月历格子的打点同读一份来源。

**分区过滤**：笔记 / 待建 / 标签（以及 AI 产出页签）面板头下方有一个过滤输入，按子串匹配文件名 / 书签标题 / 待建目标 / 标签名，切分区自动清空；AI 对话页签不渲染它——那里没有可过滤的列表，日历同样不渲染——月历与当天列表都没有「过滤」这件事。目录树过滤时会无视折叠状态展开全部目录——命中藏在收起的目录里等于没找到。点标签行会带着 `#标签` 打开全库搜索。

**笔记分区的三个标签页（目录 / 置顶 / 最近）**：置顶与最近打开不再压在目录树上方混排，而是和目录树并列成同级标签，一次只看一种视图——目录是纯文件树，置顶按你置顶的顺序排（右键文件树或书签行 →「置顶 / 取消置顶」），最近按打开时间倒序留 10 条、列表末尾一键清空，两组书签行都标出所在目录。过滤词跟着当前标签走，切标签自动清空；置顶 / 最近是本机使用习惯，不进同步。

## 日历分区（日记）

`Ctrl / ⌘ + Alt + D`（或点侧栏活动栏的日历图标）把侧栏切到日历分区——**上面月历、下面那一天的日记列表**，编辑器与右栏一动不动：日历是「按日期翻日记」的工具，不是阅读形态，不该拿整屏来换。它是第五个分区（排在标签之后、AI 之前，与笔记 / 待建 / 标签同级），故有自己的选中态与计数徽标；窄屏下它就是左侧那个全屏面板，与其它分区无异。

**月历**：周一开头，`‹ 年月 ›` 翻页 +「今天」一键归位。**格子只负责选日期**——一个日期号加一个打点（有日记的日子才有），相邻月的日子灰显但照样能点。侧栏 300px 宽切 7 列每列只有 42px，格子里放不下标题，所以篇目一律集中在下方列表，某天写了十篇也不会把整行格子撑变形。两种标记分开：环形描边是今天，淡强调底是选中——两者常常不是同一天。

**当天列表**：下半截跟着**选中日**走（默认今天），行高紧凑、长标题截断不换行，当前打开的那篇日记用 accent 淡底标出。列表头部是那一天的日期标题与「新建」按钮；两块之间是一条分隔线，月历固定高度不滚动，列表吃掉剩下的全部空间并自己滚。

**交互分工**：点**格子**选中那天（列表立刻切换），点**列表里的标题**打开那一篇（窄屏下顺带收起面板）；「新建」展开一个行内输入框，回车即按 `sanitizeTitle` 洗过的标题建文件并打开——正文不是空的，文件一出生就带着 `date: YYYY-MM-DD`（`initialDailyContent`），否则它只是日记目录下的一个普通文件、进不了日历。`Esc` 或失焦取消。先要标题再建文件，是为了不让「未命名」攒成一堆；标题洗完为空（比如输入的全是 `/`）会留在输入态并提示，不建一个空文件名出来。换了选中日会自动收掉输入框——标题是给「那一天」的，留在输入态会让人以为敲完会建到别处去。

**键盘**：日期号之间 `↑ ↓ ← →` 漫游（±1 天 / ±7 天，正好一行），目标格不在当前矩阵里会自动翻到那个月再聚焦，Tab 进网格时焦点落在今天。**漫游顺带选中那一天**——否则方向键移走了、下半截还停在原地，等于要按两次才看到目标日期。读屏的 `aria-label` 报「完整日期 + 星期 + 今天 + N 篇日记」，标题走列表而非塞进标签。

**日期是字段，不是存放位置**：日历只认 frontmatter 的 `date:`（`core/daily.ts` 的 `dailyDateOf`，`verify-daily.mts` 用 187 条断言钉死）。任何笔记写了 `date: 2026-10-10` 就是那一天的日记，**住在 `工作/` 下照样进日历**；反过来路径对而字段缺失的文件不算。于是「位置 = 含义」那条绑定被拆掉——把 `日记/会议.md` 拖进 `工作/`，它仍然躺在自己那天的列表里；旧版恰恰栽在这一步，搬走即无声失联。归日以字段为准、宽容到能认 `2026-10-10T09:30` 与带引号的写法，但**不认 `2026-02-30` 这种不存在的日子**——放它进日历，月历上会多出一个永远点不中的格子。

**新建平铺落 `日记/标题.md`**：`日记/晨间.md`、`日记/会议.md` 可以是同一天的两篇，也可以分属两天——**日期与路径彻底解耦之后，目录段就不再承载任何含义，于是干脆不要它**。标题撞了按 `标题 2 / 3 …` 退让（`uniqueDailyPath`），与 AI 笔记沉淀同一套口径；`createNote` 对占用路径是幂等早退，不先退让的话第二篇会「提示成功」却一个字都没写进去。标题仍在文件名段，`titleOf` 原样可用，与文件树 / 搜索 / 反链的显示名同源，不为日记单开一套取名逻辑。

**存量的日期目录一次性拍平**：此前那版「一天一个目录」（`日记/2026-10-10/会议.md`）留下的目录段现在只是空壳，`reconcile` 尾部的 `flattenDailyDirs` 会把它们搬到 `日记/会议.md`、清掉搬空的日期目录，并把入链一并改写。与回填同一套**自门控**：候选归零之后每次启动只是几次 map 查询。顺序排在回填之后——那时 `date:` 已经落进字段，这一步纯粹是搬家、不碰正文；中途失败留下的也是「已带字段但还在日期目录里」的中间态，下一轮接着搬。旧的单文件形态 `日记/2026-10-10.md` 与根目录的 `2026-10-10.md` **不再被当成路径特例绕开**：它们是回填认得的三种日期名形态之一，缺 `date:` 的会被补上字段、留在原地。

索引落在新的 Dexie 派生表 `dailies`（version 4，`path → date`，**每篇笔记一行**、`date` 为空表示「扫过但没有日期」），照 `links`/`tags`/`cards` 同样的待遇：保存漏斗 `reindexContent` 逐篇维护，`hydrate`/`flush`/备份按 `TABLE_FILES` 自动带上一份 `dailies.json`，随时可清空重建、不承载用户唯一数据。缺行的笔记由 `reconcile` 尾部的 `repairDailyIndex` **自门控**地补齐——升级后第一轮全库扫一遍，之后每篇都有一行、候选归零，此后一次都不用读，因此不需要「已回填」标记位。**会改写 `date:` 的只有两处**，都是「让字段跟上文件所在的那一天」：其一是回填，路径里带着日期却没有 `date:` 的文件（`日记/2026-10-10/会议.md`、`日记/2026-10-10.md`、根目录的 `2026-10-10.md`——三种历史形态都认，多半是桌面 Obsidian 写出来的）会被补上字段，并按一次真实的本地修改标脏推送；其二是**搬进**日期名文件的改名——把文件命名成 `日记/2026-10-11.md` 就是想换一天，字段跟着变。**搬出则一个字节都不改**（包括上面那次拍平）：那只是整理，日期跟着文件走。应用内保存从不回填，用户删掉 `date:` 是明确意图，该被尊重；补完仍解析不出日期的就让它缺席——宁可少一天，也不再开第二条按路径读取的规则，那会把老问题原样请回来。

## 主题与外观

设置（`Ctrl / ⌘ + ,`）→「外观」标签页，点主题卡片或强调色圆点**立即生效**，不用保存。

| 主题 | id | 明暗 | 说明 |
| --- | --- | --- | --- |
| 夜阑 | `night` | 深 | 蓝灰深色，默认 |
| 曜石 | `graphite` | 深 | 中性近黑，对比最强 |
| 极地 | `nord` | 深 | 冷调蓝灰，最柔和 |
| 白昼 | `day` | 浅 | 干净浅色 |
| 纸墨 | `paper` | 浅 | 暖色护眼 |

强调色八种：紫罗兰 `violet`（默认）、靛蓝 `indigo`、天青 `sky`、碧 `teal`、松绿 `pine`、橙 `orange`、蔷薇 `rose`、雾蓝 `mist`。用于链接、双链胶囊、选中态、任务复选框和关系图谱的节点。

选择存在 `localStorage['webvault:appearance']` 里，**只属于这台设备的这个浏览器**：不进 Gitee 仓库，不影响笔记内容，换设备各自独立。`index.html` 里有一段内联脚本在首帧之前把它写到 `<html>` 的 `data-theme` / `data-mode` / `data-accent` 上，所以选了浅色主题也不会在启动时闪一下深色。被 Safari 的防跟踪策略清掉也无所谓，顶多回到默认主题。

对比度是逐组手调的，不用公式：浅色主题会把强调色压深（例如紫罗兰 `#9182f6` → `#6a58e8`），落在强调色淡底上的文字再走一档 `--accent-text`，保证 10px 的角标也有 4.5:1。`pnpm verify` 里的 `verify-theme` 会按 WCAG 把 5 主题 × 8 强调色的组合全算一遍。

编辑器跟着一起换：明暗翻转时调用 Vditor 的 `setTheme()` 切换它自带的 dark / classic 皮肤、内容主题和代码高亮样式（`atom-one-dark` / `github`，两个都已放进 `public/vditor`，离线可用），其余颜色全部由 CSS 变量接管；关系图谱的画布读同一套令牌。

要加一套自己的主题：在 `src/styles/themes.css` 里照抄一块 `html[data-theme='x'], [data-theme-preview='x'] { ... }`（令牌必须和现有的完全一致，`data-theme-preview` 那半句是给设置页的缩略图用的），再到 `src/core/theme/themes.ts` 的 `THEMES` 里登记一行。令牌缺项、对比度不够、组件里写死了颜色，`verify-theme` 都会报出来。

## 窄屏与移动端

断点是 **960px**。窄屏下左右栏不再是「压在正文上的一条抽屉」，而是**铺满整个 body 区的互斥全屏面板**——300px 的反链 / 日历面板在 375px 屏上本来只留得出一条正文缝，压暗遮罩只是让这条缝更难读；与其两样都看不清，不如一次只看一样。因此**没有遮罩**（铺满之后没有「外面」可点），收起的入口是：面板头部左侧的 ×、顶栏那两个一直可见的开关、`Esc`，以及**打开一篇笔记时自动收起**。顶栏本身在 body 区之外，所以搜索 / 设置 / 同步在面板打开时照样可用。

**触控目标**按对象分别处理，因为它们的失败模式不同：

| 对象 | 宽屏 | 窄屏 | 手段 |
|---|---|---|---|
| 活动栏图标 | 34px（节距 37） | 40px（节距 44） | 真加高 |
| 目录树行 | 24px | 32px | 真加高，行高进 CSS 变量 |
| 日历格子 | 30px | 40px | 真加高（格子彼此紧挨，扩命中区会互相抢点击） |
| 顶栏图标钮 | 28px | 40px 高，命中区补齐到 32×44 | 高度真加、宽度靠伪元素补 2px（六个按钮已占 168px，再加宽就轮到标题没地方站） |

活动栏指示条的位移原本是模板里硬编码的 `下标 × 37`，改成 `--idx × --rail-pitch` 之后节距进了媒体查询，两处不用再互相追着改。

**目录树的行高只有一个定义处**：CSS 的 `--row-h`（`.tree` 上声明，窄屏覆盖成 32px），虚拟化脚本在挂载与断点变化时把它读回来算窗口切片。过去是「JS 常量 + CSS 像素」双写，任何一处漏改都会让切片算错而**掉行**——现在改 CSS 就等于改了计算口径。

**顶栏**：六个图标钮 + 锁 + 落盘徽标把标题挤成两三个字是这一档真正的矛盾。窄屏下落盘徽标缩成一个 7×7 的状态色圆点，腾回约 69px；**文案没有丢**，`font-size: 0` 只让它退出布局，DOM 与无障碍树里都还在。同时删掉了 `.topbar__title` 上 `max-width: 42vw` 这个有害的上界——空间紧的时候它不起作用（flex 自会收窄标题），空间宽裕的时候却把标题卡死，白白浪费中间的空白。

**安全区**：`index.html` 已带 `viewport-fit=cover`，所以顶栏补 `padding-top: env(safe-area-inset-top)`，侧栏 / 右栏 / 编辑器 / 对话框底部补 `env(safe-area-inset-bottom)`。`env()` 在没有刘海或 Home 指示条的机型上是 0，因此**无条件加、不需要再套媒体查询**。顶栏用 `min-height` 而不是 `height`：`border-box` 下写死 `height: 44px` 会把安全区吃进 44 里，子元素直接溢出到状态栏上。

**本轮没有动的**：编辑器工具栏仍然是 `display:none`，`# ` / `- ` / `[[` 在手机上仍要靠手打——「界面只留正文」是当初刻意的产品决策，要改值得单独一轮。右键菜单在触屏上靠文件树的 ⋯ 按钮（触屏无 hover，故它常显）。

## AI 助手

浏览器**直连 OpenAI 兼容 API**：在 设置 → AI 里自填 `baseUrl` / API Key / 模型名（预设了 DeepSeek、Kimi、SiliconFlow、OpenRouter 四家，点一下回填，「测试连接」试通再保存）。请求只发往你自己填的地址；API Key 明文存本机 `.webvault/ai.json`，导出备份时被自动抹空（`verify-redact` 钉住），共享整个文件夹前连同它一起清掉。供应商不允许浏览器跨域（CORS）时会报错并提示换一家或自建中转——本项目没有后端，也绝不经手你的 Key。

三个入口，全部是**显式动作**：

- **侧栏「AI」分区**（`Ctrl/⌘ + Alt + A`）：对话页签支持多轮问答与流式输出（可随时停止）；「引用当前笔记」把正文带进上下文（发送前显示可摘掉的引用芯片，长文自动裁剪），随后出现 总结 / 标签 / 双链建议 的快捷动作；产出页签列出 `ai/` 目录里沉淀过的笔记，可按标题过滤
- **选区浮层**：编辑器里选中一段文字，选区旁浮出 🤖 按钮 —— 改写 / 润色 / 续写 / 总结 / 翻译 / 解释，流式生成后「插入到下方」（原文保留）或「替换选中」（会删原文，因此是单独一个按钮、生成完成后才可点）
- **存为笔记**：对话会话栏的「存为笔记」把问答誊录沉淀成 `ai/<标题>.md`（重名自动加序号）

### AI 与自己的思考分隔开

- **存放分隔**：对话历史存本机 `.webvault/ai-chats.json`（settings 表的一个键），不进笔记库、不进搜索索引、不随同步推 Gitee —— 聊天是草稿，只有显式「存为笔记」才落成 `.md`（那是定稿，会随同步走）
- **标记分隔**：AI 内容进笔记必带双重标记 —— frontmatter 的 `ai:` 块（模型 / 时间 / 来源）+ 正文里的可见声明行；一切插入都被包在 `> 🤖` 引用块里，**没有任何裸插路径**：标记只由 `core/ai/marks.ts` 生成，出口只有 `aiQuoteBlock`（插入）与 `buildAiNoteContent`（沉淀）两个，由 `verify-ai-prompts` 逐条钉住
- **浏览分隔**：侧栏第 5 个分区专属 AI（对话 / 产出两个页签）；`ai/` 目录与其中的笔记在文件树带 🤖 角标，判定与「产出」列表共用同一个 `isAiPath`
- **不越权**：AI 永远不会自己动笔记 —— 保存、插入、替换、沉淀每个都是用户点下的按钮；面板里发出去的每段上下文（引用芯片）也由用户显式添加、显式摘除

## 数据存在哪里

| 内容 | 位置 | 说明 |
| --- | --- | --- |
| 笔记正文 | OPFS（源私有文件系统） | 明文 `.md`，目录结构和仓库里一致；文件开头已有的 frontmatter 原样保留、永不改写（安全网：若保存时发现元数据块消失，会拒绝写入并还原） |
| 配置与索引（`.webvault/` 下的 12 个 JSON） | vault 根（绑定目录或 OPFS 根） | 文件为真相源，Dexie（库名 `webvault`）只是运行时缓存；设置里有「重建链接与标签索引」按钮 |
| 主题与强调色 | `localStorage` | 见「主题与外观」 |

库根的形状对齐 Obsidian —— 根下只有笔记与目录，全部元数据、索引、设置收进一个隐藏配置目录：

```
库根/                          绑定的文件夹;未绑定时是浏览器 OPFS 根
├── 日记/晨间.md                日记;平铺不按天分目录,归日看 frontmatter 的 date
├── 素材/图.png                附件(只索引,不上传)
└── .webvault/                 隐藏配置目录,对标 Obsidian 的 .obsidian
    ├── sync.json              Gitee 同步配置 —— 含明文 token,单独成文件,共享前先清它
    ├── ai.json                AI 连接配置 —— 含明文 API Key,单独成文件,共享前连它一起清
    ├── ai-chats.json          AI 对话历史(本机草稿,不进笔记库、不推 Gitee)
    ├── app.json               静态设置
    ├── hotkeys.json           可改的快捷键绑定
    ├── workspace.json         工作区状态:上次打开、最近、置顶、折叠(高频变动)
    ├── notes.json             笔记索引:三方合并的三个 sha、dirty / cached / mtime
    ├── links.json             双链索引
    ├── tags.json              标签索引
    ├── cards.json             卡片元数据(供永久 ID 链接解析)
    ├── dailies.json           日历索引:每篇的 frontmatter date,空串表示「扫过、没有日期」
    └── sync-log.json          同步日志(滚动约 300 条)
```

配置目录名与「表 → 文件」的分流规则只有一个出处：`src/core/vault/config-layout.ts`（纯模块，由 `verify-config-layout` 钉住）。旧版库的 `.config/settings.json` 会在启动时一次性拆搬进上面按职责分出的小文件，搬完即删旧目录。

这些都只在这台设备上，不会发往 `gitee.com` 以外的任何服务器。

**你的 Gitee 仓库就是备份，也是导出格式**——里面是普通 `.md` 文件，可以直接用 Obsidian、VS Code 或任何编辑器打开。换设备时，新设备打开应用、填同一个仓库配置、同步即可。应用会主动申请持久化存储授权（设置里能看到是否已授权），降低被浏览器自动清理的概率。

不想只依赖 Gitee 的话，「设置 → 数据与日志」里有**「导出备份 (zip)」**：把本机当前读得到的全部正文按原目录结构（含中文目录）打成一个 zip 下载，另在 `.webvault/` 下放一份导出时刻的配置与索引快照和一份 `README.txt`——目录名、文件名都与库内原件一致，解压出来可以整份 diff。几处刻意的取舍：

- **只读**，应用不支持从 zip 导入（恢复 = 把解压出的 `.md` 放回笔记目录，或重新连回 Gitee 同步）。
- **不带 Gitee 令牌**——快照里的凭据字段在导出时被置空，键保留、值留空，方便你和 `.webvault/sync.json` 原件对 diff；同步日志是滚动窗口，也一并不带。
- **以磁盘为清单**：索引里标着「已缓存」而盘上读不到的正文会如实计入回执并单独弹一条警告，绝不静默少几篇。
- 每篇的 `lastModified` 一并写进 zip，恢复出来的文件保留原来的修改时间。

## 同步是怎么做的

每篇笔记存三个 git blob sha：

- `baseSha` —— 上次同步成功时双方一致的**共同祖先**，三方合并全靠它
- `localSha` —— 本机 OPFS 里正文的 sha
- `remoteSha` —— 最后一次在远端看到的 sha

**拉取**：一次文件树请求搞定全库索引。远端新增的笔记建「仅索引」stub；远端已经没有、而我们曾经推过的笔记标记为「远端已删除」，随后删除本机副本和索引（若本地此时有未上传的修改，则保留本地版本并重新上传，同时给一条提示）。

**推送**：把脏文件和删除墓碑打包成一次多文件提交，单次最多 40 个 action，超出就分批。如果部署的 Gitee 不提供多文件提交接口（404/405），自动降级为逐文件提交，而不是让整次同步失败。

**两边都改了同一篇**：取祖先 blob 做三方合并。能自动合并的直接合并；合不了的**保留本地版本**，把远端版本另存为 `标题.conflict-时间戳.md`，两个文件都上传——不会往正文里插冲突标记，也不会静默覆盖任何东西。

**限流处理**：Gitee 的限流响应头跨域读不到，配额只能撞上才知道。所以策略是可重试错误做指数退避（1s→2s→4s…最多 4 次，上限 60s），后台预取一旦失败立即中止而不是继续烧配额。

## 已知限制

- 附件（图片等）只会被当作链接索引进「待创建」列表，**不支持预览或上传**。
- `![[嵌入]]` 不会内联渲染，`[[笔记#小节]]` 跳转后也不会自动滚动到该小节——锚点部分只用于索引与反链展示，导航时会被忽略。（要按小节跳过去，用右栏「大纲」页签：它走的是编辑器自己的标题序列，与双链锚点是两条互不相干的路。）
- Vditor 即时渲染模式在首次编辑时会规范化部分 Markdown 语法（列表符号、空行等），这是编辑器内核的行为，不是同步造成的。
- 和桌面版 Obsidian 可以共用同一个 git 仓库（都是普通 `.md` + `[[双链]]`）；**iOS 版 Obsidian 没有 git 同步，无法直接互通**。
- 只同步 `.md` 文件。仓库里的其它文件既不会被下载，也不会被删除。
- 仓库文件过多导致 Gitee 返回被截断的文件树时，本次同步不完整，会给一条警告。
- 三方合并按行工作，不认识 YAML。两台设备分别改同一个 frontmatter 键时，合并结果可能出现重复的键。应用会**保留第一处并给出提示**，请自己在编辑器里清理；绝不会有键被静默改写或删掉。
- 没有版本历史界面，也没有多用户协作模型；历史请直接去 Gitee 网页看提交记录。
- 「导出备份 (zip)」只能导出、不能导入。恢复靠放回笔记目录或重新连 Gitee；导入要处理三方合并、删除墓碑与同步三元组的冲突，是另一个量级的问题，没有含糊地做半套。

## 安全须知

**私人令牌以明文保存在这台设备的浏览器 IndexedDB 里**，只会被发往 `gitee.com`。请据此判断：

- 公用电脑、共享设备、别人的浏览器**不要填令牌**。
- 令牌只勾 `projects` 权限，并用一个专门放笔记的私有仓库，这样即使泄露影响也有限。
- 怀疑泄露就立刻去 Gitee 撤销令牌并重新生成，然后在设置里更新。
- 「导出备份 (zip)」**不携带令牌**：`.webvault/sync.json` 里的凭据字段在导出时就被置空（`core/vault/redact.ts`，由 `verify-redact` 断言钉住）。但**绑定目录里的 `.webvault/sync.json` 仍是明文**，共享整个文件夹前要自己清掉。
- 笔记在仓库里是明文 `.md`，**没有端到端加密**。仓库务必设为私有；不要把存笔记的仓库和公开项目放在一起。
- 本应用不收集任何数据，也没有第三方统计或 CDN 依赖。
