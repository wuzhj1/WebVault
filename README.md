# WebVault

本地优先的 Markdown 双链笔记。纯静态单页应用，没有账号、没有后端：正文以明文 `.md` 存在浏览器里，通过**你自己的 Gitee 仓库**在设备之间同步。

- 双链 `[[笔记]]`、别名 `[[路径|显示名]]`；`[[笔记#小节]]`、`[[笔记#^block]]`、`![[笔记]]` 会被解析并索引，在反链面板上标注出来，重命名时原样保留
- 编辑器里的双链**直接渲染成可点击的链接**：方括号和别名前的路径隐藏，只显示你要读的那段文字；已存在的笔记是实色胶囊，还没创建的目标是虚线灰字（点一下就建），附件用点线区分。光标进入某一行时该行自动展开成原始 markdown，方便改写链接本身
- 反向链接 / 出链 / 待创建目标面板，点击不存在的链接直接建笔记
- 重命名或移动笔记时，全库指向它的 `[[双链]]` 自动改写
- 卡片盒笔记法：卡片有写进文件的**永久 ID**，`[[202609151423]]` 和 `[[干净标题]]` 都能解析，改名不会断链
- 闪念 → 文献 → 永久 → 索引 四种卡片类型，侧栏「卡片」页给出收件箱、孤儿卡与全部列表
- 相关卡片：共引、同源、共同标签、文本相似、引用了我而我没回引，五种信号打分并给出理由
- 中文全文搜索（自研 CJK 单字/双字分词 + MiniSearch），带命中摘要
- 力导向关系图谱
- Vditor 即时渲染编辑器，`[[` 触发链接补全，资源全部自托管、离线可用
- 5 套主题（3 深 2 浅）× 8 种强调色，在设置的「外观」里点一下就换，编辑器、代码高亮、关系图谱一起跟着走
- PWA：可安装、可离线，Safari 清空缓存后能自动从 Gitee 恢复
- Gitee 单仓库同步：索引优先拉取、正文按需下载、批量提交、三方合并、冲突副本

## 本地跑起来

```bash
npm install
npm run dev        # http://localhost:5173
```

不配置同步也能当纯本地笔记用，所有功能（双链、搜索、图谱）都在本机完成。

自检命令：

```bash
npm run verify     # 8 个验证套件,525 条断言(配置 / 解析 / 卡片盒 / 链接改写 / 三方合并 / 远端删除判定 / 搜索 / 主题)
npm run typecheck  # vue-tsc --noEmit
npm run build      # 先重新生成 PWA 图标,再产出 dist/
```

浏览器要求：Chrome / Edge 86+、Firefox 111+、Safari 15.2+，且必须是 **HTTPS 或 localhost**（OPFS 与 Service Worker 只在安全上下文可用，用 `http://` 打开会直接提示不支持）。

## 部署

`npm run build` 产出 `dist/`，丢到任意静态托管即可：Nginx、Vercel、Netlify、Cloudflare Pages、GitHub Pages、Gitee Pages。

Service Worker 已配置 `navigateFallback`，深链接刷新能回到应用；托管侧最好也把未知路径重写到 `index.html`。`gitee.com` 的请求被强制设为 `NetworkOnly`，同步的正确性依赖每次拿到最新的 sha，绝不能吃缓存。

### 子路径部署（Gitee Pages / GitHub Pages 项目页）

站点不在域名根目录时（例如 `https://user.gitee.io/my-vault/`），构建前要告诉 Vite 基础路径。在项目根目录新建 `.env.local`：

```
VAULT_BASE=/my-vault/
```

然后正常 `npm run build`。`start_url`、`scope`、静态资源、Service Worker 回退路径、Vditor 的资源目录都会跟着加上这个前缀。

> **Windows / Git Bash 注意**：不要用 `VAULT_BASE=/my-vault/ npm run build` 这种命令行写法。MSYS 会把以 `/` 开头的参数改写成 Windows 路径（`/my-vault/` 变成 `D:/soft/Git/my-vault/`），构建结果全错。写进 `.env.local` 最稳妥；确实要用命令行就加 `MSYS_NO_PATHCONV=1`。`.env.local` 已被 `.gitignore` 的 `*.local` 规则忽略。

### Gitee Pages 流程

1. 把 `dist/` 的内容提交到一个仓库（这个仓库可以和存笔记的仓库分开，也可以就是同一个仓库的 `gh-pages` 之类分支）。
2. 在仓库的「服务 → Gitee Pages」里开启，拿到 `https://<用户名>.gitee.io/<仓库名>/`。
3. 按上面写 `.env.local` 再构建一次，重新部署。

## 第一次配置 Gitee 同步

1. 在 Gitee 新建一个**私有**仓库（例如 `my-vault`），**里面至少提交一个文件**——空仓库没有分支，推不上去。建议专门用一个仓库放笔记，不要和代码混在一起。
2. 打开 `gitee.com/profile/personal_access_tokens`，生成新令牌，**只勾选 `projects`**。
3. 在应用里按 `Ctrl/⌘ + ,` 打开设置 →「Gitee 同步」，填：
   - **私人令牌** access token
   - **空间地址** owner（用户名或组织名；直接把 `gitee.com/<owner>/<repo>` 的仓库地址整串粘进来也行，保存时会自动拆成 owner / repo / branch 三段）
   - **仓库名** repo
   - **分支** branch（默认 `master`）
4. 点「测试连接」，成功会显示分支、HEAD 短 sha 和文件数。
5. 点「立即同步」把远端笔记拉到本机。

首次同步只用一次 `trees?recursive=1` 请求建立整个文件索引，没下载正文的笔记是「仅索引」状态（设置 →「数据与日志」里能看到数量）；打开某篇时才按需下载正文，后台每轮预取 25 篇慢慢补齐。这样即使仓库里有几千篇笔记，第一次同步也不会打爆 Gitee 的接口配额。

「编辑后自动同步」默认开启，推送延迟默认 15 秒（停止输入 15 秒后尝试上传）。把延迟调长能减少提交次数，避免仓库塞满碎片提交。

## 装成应用（PWA / 添加到主屏幕）

- **桌面 Chrome / Edge**：地址栏右侧的安装图标，点一下就以独立窗口运行。
- **Android Chrome**：菜单 →「安装应用」或「添加到主屏幕」。
- **iOS Safari**：分享按钮 →「添加到主屏幕」。**必须这样做**，见下。

### iOS 上为什么要装到主屏幕

Safari 的防跟踪策略（ITP）会在大约 7 天不使用后清空该站点的全部本地数据，包括 OPFS 里的笔记正文。装到主屏幕能显著降低被清的概率，但并不能完全避免。

因此应用启动时会自检：如果 IndexedDB 的索引还在、OPFS 正文却空了，就判定为「浏览器清空了缓存」，自动从 Gitee 重新拉取全部正文并显示进度，完成后提示恢复了多少篇。也可以在「数据与日志」里手动点「清空并重新下载」触发同一条恢复路径（该按钮在还有待上传文件时是禁用的，防止覆盖掉未同步的修改）。

**前提是配了同步**。没配 Gitee 就只有一份本机数据，被浏览器清掉就是真丢了。

离线方面：应用外壳、样式、编辑器内核（Vditor 的 lute、图标、katex 等资源全部放在 `public/vditor`，不依赖任何外部 CDN）都在 Service Worker 的预缓存里，断网也能正常读写笔记，联网或切回前台时自动同步。

重新部署后不需要用户手动清缓存：Service Worker 是 `autoUpdate` 模式，新版本会在后台自动安装并接管，下一次刷新（或下一次打开已安装的应用）就是新版本。实测是「部署 → 打开一次触发更新 → 再刷新一次拿到新界面」。

## 卡片盒笔记法（Zettelkasten）

双链解决的是「怎么连」，卡片盒解决的是「怎么加工」：每张卡有一个永不变的地址，想法从闪念一路做到永久卡片，没有链接的卡片会被指出来。

### 元数据写在文件里

卡片的信息写在 `.md` 开头的 YAML 块里，因为**只有写进文件才会跟着 Gitee 同步**——存在 IndexedDB 或 localStorage 里换台设备就没了，「永久地址」也就没有意义。

```yaml
---
id: 202609151423
type: fleeting
created: 2026-09-15 14:23
tags: [卡片盒, 笔记法]
aliases: [Zettelkasten]
---
```

应用只拥有这 5 个键。块里的其它键（`slug:`、`cssclasses:`、`publish:`）、注释行、嵌套映射一律**原样保留、永不重写**；改一个键时其余行的字节都不动，所以不会因为写元数据而在仓库里制造无谓的 diff。

在编辑器里这个块是可见的文本，显示成等宽小字加一条左侧色条，读起来像文件属性而不是正文。Vditor 的即时渲染内核原生把它识别为 front matter 节点，往返保真已逐字节验证过。

### ID 与文件名

ID 是 12 位本地时间戳（`202609151423` = 2026-09-15 14:23）。同一分钟里再建一张就加字母后缀：`…1423a`、`…1423b`，一直到 `z` 再进位到 `aa`。用字母而不是 `-1`：连字符和下划线在链接解析和标题提取眼里是词边界，字母后缀则正好排在裸时间戳后面。

新卡片默认命名成 `202609151423 卡片盒笔记法.md`，可以在设置里关掉前缀。**但文件名只是外观，文件里的 `id` 才是地址**：

- `[[202609151423]]` 和 `[[卡片盒笔记法]]` 都能解析到同一张卡；
- 把文件改名成 `卡片盒笔记法.md`（去掉前缀）之后，`[[202609151423]]` 照样能解析；
- 界面上显示的标题永远是干净的：文件树、顶栏、反链、图谱标签都会剥掉开头的 ID 前缀；
- 真有一篇笔记就叫 `202609151423.md` 时，按路径和文件名解析优先，ID 查表是最后一级。

### 四种类型

| 类型 | 文件里的值 | 意思 |
| --- | --- | --- |
| 闪念 | `fleeting` | 随手记下、还没想清楚的草稿，会留在收件箱里等处理 |
| 文献 | `literature` | 记下别人的说法与出处 |
| 永久 | `permanent` | 想清楚了的原子卡片，一张只说一件事 |
| 索引 | `index` | 一组卡片的目录（MOC） |

没有元数据块的笔记类型显示为「普通」，不是第五种可选项——它是「这篇还不是卡片」的意思。

流转在哪里体现：

- **侧栏「卡片」页**，页内切 `收件箱 / 孤儿 / 全部`。收件箱是所有闪念卡，按创建时间升序，压得最久的排最前；全部按创建时间降序。
- **右栏「信息」页**有一排类型按钮，点一下就改。给一篇普通笔记点类型，等于把它提升为卡片：会补上 `id`、`type` 和 `created`（用这篇笔记自己的修改时间，而不是现在——存了一年的笔记不该声称自己是刚写的）。
- **右栏「链接」页的「相关卡片」分组**，每行带一句理由，例如 `共引 3 · 同标签 1`。
- **关系图谱**里孤儿卡片画成空心点，还有一个「只看孤儿卡」开关。

改类型是安全的：调用前会先把编辑器里防抖中的正文强制落盘并等它完成，再读文件、改元数据、写回去，最后让编辑器重读。所以连续打字后立刻改类型，既不会丢最后几次按键，改类型也不会被随后的防抖保存覆盖掉。

### 相关卡片怎么算

五种信号加权求和，全部来自已有的索引，不额外读正文：

| 信号 | 理由标签 | 含义 |
| --- | --- | --- |
| 共引 | `共引 N` | 另一张卡和我指向同一个目标 |
| 同源 | `同源 N` | 我指向的某张卡又指向了它 |
| 共同标签 | `同标签 N` | 按 Jaccard 相似度，所以一张挂了 20 个标签的卡不会匹配一切 |
| 文本相似 | `文本相似` | 用全库搜索给正文打分，**只在索引已经建好时启用**，绝不为了这个面板去扫全库 |
| 引用了我 | `引用了我` | 它引了我而我没有回引——这正是卡片盒最该浮出来的不对称 |

两个链接信号都会按中间节点的出度或入度衰减：所有人都在链的索引页不该统治结果。覆盖超过 15% 全库的标签视为枢纽标签，不参与候选发现。直接的出链邻居被排除在外，因为它们已经在「出链」里列着了。

### 孤儿卡片

没有任何**能解析的**双链（出链或入链）的卡片就是孤儿。指向一个还不存在的目标不算连接，`[[自己]]` 也不算。侧栏的孤儿列表和图谱的空心点用同一个纯函数判定，两个界面永远不会打架。

孤儿行的副标题会区分两种情况：写了链接但目标还没创建的，显示 `n 个待建链接`；真的一条链接都没写的，显示类型。

### 旧笔记永远不会被改动

这是硬约束，不是默认值：

- 建立卡片索引的过程对 OPFS **严格只读**，只写 IndexedDB 里的派生表；
- 没有元数据块的笔记类型就是「普通」，不进收件箱，也不会被自动补上 frontmatter；
- 想给某篇旧笔记加上元数据，只能你自己去右栏「信息」页点类型——那是唯一的写入入口；
- 卡片索引随时可以清空重建（设置 →「卡片盒」→「重建卡片索引」），因为它只是正文的派生物。

另外装了一张安全网：如果编辑器交回来的正文里开头的元数据块消失了，这次保存会被**拒绝并还原**，同时给一条提示。卡片块被静默删掉意味着这张卡的永久地址没了，而且会被推到 Gitee 上；拒绝写入把这个灾难性且不可见的失败变成可见可恢复的。真要清空的话，保留首尾两行 `---`、只删掉里面的内容即可。

### 卡片盒设置只属于这台设备

设置 →「卡片盒」里的两项（文件名是否带 ID 前缀、新建卡片的默认类型）存在本机浏览器里，**不会同步**。卡片自己的 `id` / `type` / `created` / `tags` / `aliases` 在文件里，照常跟着仓库走。

缓解办法：从没手动设置过时，应用会照着仓库现状推断——有 ID 的卡片里超过 60% 的文件名以该 ID 开头，就认为这个库用前缀命名。所以第二台设备通常会自动收敛到第一台的选择。推断出来的值**不会写回**，否则它就粘住了、再也覆盖不掉。

这一页用的是「改完要点保存」的模式，不像外观页那样点一下就生效：这些设置决定接下来几十个文件叫什么名字，误点不该悄悄改掉。

## 主题与外观

设置（`Ctrl / ⌘ + ,`）→「外观」标签页，点主题卡片或强调色圆点**立即生效**，不用保存。

| 主题 | id | 明暗 | 说明 |
| --- | --- | --- | --- |
| 夜阑 | `night` | 深 | 蓝灰深色，默认 |
| 曜石 | `graphite` | 深 | 中性近黑，对比最强 |
| 极地 | `nord` | 深 | 冷调蓝灰，最柔和 |
| 白昼 | `day` | 浅 | 干净浅色 |
| 纸墨 | `paper` | 浅 | 暖色护眼 |

强调色八种：紫罗兰 `violet`（默认）、靛蓝 `indigo`、天青 `sky`、碧 `teal`、松绿 `pine`、橙 `orange`、蔷薇 `rose`、雾蓝 `mist`。用于链接、双链胶囊、选中态、任务复选框和关系图谱的节点。

选择存在 `localStorage['webvault:appearance']` 里，**只属于这台设备的这个浏览器**：不进 Gitee 仓库，不影响笔记内容，换设备各自独立。`index.html` 里有一段内联脚本在首帧之前把它写到 `<html>` 的 `data-theme` / `data-mode` / `data-accent` 上，所以选了浅色主题也不会在启动时闪一下深色。被 Safari 的防跟踪策略清掉也无所谓，顶多回到默认主题。

对比度是逐组手调的，不用公式：浅色主题会把强调色压深（例如紫罗兰 `#9182f6` → `#6a58e8`），落在强调色淡底上的文字再走一档 `--accent-text`，保证 10px 的角标也有 4.5:1。`npm run verify` 里的 `verify-theme` 会按 WCAG 把 5 主题 × 8 强调色的组合全算一遍。

编辑器跟着一起换：明暗翻转时调用 Vditor 的 `setTheme()` 切换它自带的 dark / classic 皮肤、内容主题和代码高亮样式（`atom-one-dark` / `github`，两个都已放进 `public/vditor`，离线可用），其余颜色全部由 CSS 变量接管；关系图谱的画布读同一套令牌。

要加一套自己的主题：在 `src/styles/themes.css` 里照抄一块 `html[data-theme='x'], [data-theme-preview='x'] { ... }`（令牌必须和现有的完全一致，`data-theme-preview` 那半句是给设置页的缩略图用的），再到 `src/core/theme/themes.ts` 的 `THEMES` 里登记一行。令牌缺项、对比度不够、组件里写死了颜色，`verify-theme` 都会报出来。

## 快捷键

| 键 | 作用 |
| --- | --- |
| `Ctrl / ⌘ + K` | 链接选择器：`Enter` 跳转到笔记，`Ctrl/⌘ + Enter` 在光标处插入 `[[双链]]` |
| `Ctrl / ⌘ + F` | 全库搜索：`↑ ↓` 选择，`Enter` 打开 |
| `Ctrl / ⌘ + ,` | 打开设置 |
| 单击链接 | 编辑器里的双链胶囊：跳转到目标笔记，目标不存在则直接创建 |
| `Ctrl / ⌘ + 单击` | 光标所在行（该行展开为原始 markdown）里的 `[[链接]]`：跳转或创建 |
| 输入 `[[` | 触发链接补全 |
| 行首输入 `/` | 斜杠命令菜单：标题、列表、任务、引用、代码块、表格、分割线、日期 |
| `Esc` | 关闭搜索 / 图谱 / 设置 / 各类弹窗 |

工具栏已移除，界面只留正文。格式操作的三个入口：行首 `/` 斜杠命令、行首 markdown 输入规则（`# `、`- `、`1. `、`> `、`- [ ] `、` ``` `）、键盘快捷键（`Ctrl/⌘ + B` 加粗、`Ctrl/⌘ + I` 斜体、`Ctrl/⌘ + Z` 撤销等）。

## 数据存在哪里

| 内容 | 位置 | 说明 |
| --- | --- | --- |
| 笔记正文 | OPFS（源私有文件系统） | 明文 `.md`，目录结构和仓库里一致；卡片的 `id`/`type`/`created`/`tags`/`aliases` 就写在文件开头，所以会跟着同步 |
| 链接 / 标签 / 卡片索引、设置、同步日志 | IndexedDB（库名 `webvault`） | 全部是正文的派生物，可随时重建；设置里有「重建链接与标签索引」和「重建卡片索引」两个按钮 |
| 主题与强调色 | `localStorage` | 见「主题与外观」 |

这些都只在这台设备上，不会发往 `gitee.com` 以外的任何服务器。

**你的 Gitee 仓库就是备份，也是导出格式**——里面是普通 `.md` 文件，可以直接用 Obsidian、VS Code 或任何编辑器打开。换设备时，新设备打开应用、填同一个仓库配置、同步即可。应用会主动申请持久化存储授权（设置里能看到是否已授权），降低被浏览器自动清理的概率。

## 同步是怎么做的

每篇笔记存三个 git blob sha：

- `baseSha` —— 上次同步成功时双方一致的**共同祖先**，三方合并全靠它
- `localSha` —— 本机 OPFS 里正文的 sha
- `remoteSha` —— 最后一次在远端看到的 sha

**拉取**：一次文件树请求搞定全库索引。远端新增的笔记建「仅索引」stub；远端已经没有、而我们曾经推过的笔记标记为「远端已删除」，随后删除本机副本和索引（若本地此时有未上传的修改，则保留本地版本并重新上传，同时给一条提示）。

**推送**：把脏文件和删除墓碑打包成一次多文件提交，单次最多 40 个 action，超出就分批。如果部署的 Gitee 不提供多文件提交接口（404/405），自动降级为逐文件提交，而不是让整次同步失败。

**两边都改了同一篇**：取祖先 blob 做三方合并。能自动合并的直接合并；合不了的**保留本地版本**，把远端版本另存为 `标题.conflict-时间戳.md`，两个文件都上传——不会往正文里插冲突标记，也不会静默覆盖任何东西。

**限流处理**：Gitee 的限流响应头跨域读不到，配额只能撞上才知道。所以策略是可重试错误做指数退避（1s→2s→4s…最多 4 次，上限 60s），后台预取一旦失败立即中止而不是继续烧配额。

## 已知限制

- 附件（图片等）只会被当作链接索引进「待创建」列表，**不支持预览或上传**。
- `![[嵌入]]` 不会内联渲染，`[[笔记#小节]]` 跳转后也不会自动滚动到该小节——锚点部分只用于索引与反链展示，导航时会被忽略。
- Vditor 即时渲染模式在首次编辑时会规范化部分 Markdown 语法（列表符号、空行等），这是编辑器内核的行为，不是同步造成的。
- 和桌面版 Obsidian 可以共用同一个 git 仓库（都是普通 `.md` + `[[双链]]`）；**iOS 版 Obsidian 没有 git 同步，无法直接互通**。
- 只同步 `.md` 文件。仓库里的其它文件既不会被下载，也不会被删除。
- 仓库文件过多导致 Gitee 返回被截断的文件树时，本次同步不完整，会给一条警告。
- 两台设备在**同一分钟**各建一张卡片，会得到两个写着相同 `id` 的文件。没有协调者时这不可避免，但也无害：路径不同，`[[id]]` 按固定规则取其中一个。真要区分，改其中一个文件的 `id` 即可。
- 三方合并按行工作，不认识 YAML。两台设备分别改同一张卡的 `type:` 和 `tags:` 时，合并结果可能出现重复的键。应用会**保留第一处并给出提示**，请自己在编辑器里清理；绝不会有键被静默改写或删掉。
- 没有版本历史界面，也没有多用户协作模型；历史请直接去 Gitee 网页看提交记录。

## 安全须知

**私人令牌以明文保存在这台设备的浏览器 IndexedDB 里**，只会被发往 `gitee.com`。请据此判断：

- 公用电脑、共享设备、别人的浏览器**不要填令牌**。
- 令牌只勾 `projects` 权限，并用一个专门放笔记的私有仓库，这样即使泄露影响也有限。
- 怀疑泄露就立刻去 Gitee 撤销令牌并重新生成，然后在设置里更新。
- 笔记在仓库里是明文 `.md`，**没有端到端加密**。仓库务必设为私有；不要把存笔记的仓库和公开项目放在一起。
- 本应用不收集任何数据，也没有第三方统计或 CDN 依赖。

## 项目结构

```
src/
  core/
    db.ts              Dexie:notes / links / tags / cards / settings / syncLog
    vault/             OPFS 读写、路径规范化、git blob sha
    editor/            编辑器内双链胶囊的 DOM 装饰(字符原样保留,不影响 Lute 序列化)
    index/             双链与标签解析、链接目标解析规则(含按 ID 解析)
    parse/             Markdown 扫描:[[链接]]、#标签、标题锚点;frontmatter 的逐行无损读写
    search/            CJK 分词 + MiniSearch 索引与摘要
    sync/              gitee API、同步引擎、三方合并、远端删除判定
    theme/             主题与强调色注册表、对比度计算
    zettel/            卡片:ID 与文件名、元数据行、新卡模板、孤儿判定、相关度打分、设置推断
  stores/              Pinia:vault(笔记与索引) / zettel(卡片生命周期) / sync(同步与通知) /
                       settings / appearance
  components/          TopBar、SideBar、FileTree、NoteEditor、RightPanel、
                       SearchPanel、LinkPicker、GraphView、SettingsDialog、Notices
scripts/               图标生成 + 8 个 Node 验证套件(npm run verify)
public/vditor/         自托管的编辑器资源,离线可用
```

`core/parse/frontmatter.ts` 和 `core/zettel/*` 是纯函数模块，有两条硬约束：**只用相对导入**（验证脚本以 `node scripts/*.mts` 直跑，没有 `@/` 别名解析），且**不得在运行时导入 `db.ts`**（它在模块作用域就构造 Dexie，需要 IndexedDB）。用 `import type` 引类型是安全的，编译后会被擦除。违反任一条，验证脚本会静默失效或直接崩掉。
